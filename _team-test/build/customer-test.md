# Customer test: first-time visitor booking Gudauri winter or a transfer

Tester: customer-test (read-only). Method: GET requests against the dev server at http://localhost:3000 (status codes, HTML, titles, meta, links, images), the built-in browser at 1366px and 375px (read only: no forms, sign-ins, chat or bookings), and a read of the code. Date of test: 21 Oct 2026.

What already works: every internal link resolves (no `/tours` link left; `/tours` and `/tours/:slug` return 308 to `/activities…`), all 17 trip pages and every image `src` on the main pages return 200, there is no horizontal scroll on the trip page at 375px, non-bookable trips show "Unavailable for now", and the date sent to the API is built locally (no UTC shift).

## Broken

- [High] lib/tours-data.js:51-55 + 652 (and findTour ~677) — Gudauri lessons (120 ₾, 2 h) have no `included` list of their own, so they fall back to the `ski` defaults. The live page lists "Accommodation: hotel in resort, breakfast included", "Transport: Tbilisi return transfer", "Lift pass for every riding day" and "Avalanche kit". Snowmobile and paragliding could do the same if their DB rows have no list; customer impact: a tourist books a 120 ₾ lesson expecting a hotel and a transfer, which leads to disputes and refunds; fix: give lessons, snowmobile and paragliding their own included/excluded lists (or an empty fallback for `subtype` lessons/snowmobile/paragliding).
- [High] components/SiteFooter.js:237-238, app/contact/page.js:13-17 — the footer and contact page still show a placeholder phone `+995 000 000 000` (also used as "Phone & WhatsApp") and `hello@torito.ge` on an xnomads.ge site. Out of scope in BRIEF, but still broken for customers; customer impact: the only ways to reach the team other than chat are dead, and the contact form opens a mail to that address; fix: owner supplies the real phone, WhatsApp and email, then set them once in a shared constant.
- [High] app/page.js:175-180 — the home page "Transfer" feature is still tagged "Coming soon" with "We are still putting the vehicles together", even though transfers are one of only two bookable things this season; customer impact: visitors think they cannot book a transfer; fix: change the tag to e.g. "Airport and resort" and drop the "still putting together" sentence.
- [High] app/api/bookings/route.js:98-100 — the server stores `total` exactly as the browser sends it, and never checks `wanted_date` (format, past date, season) or `isBookable()`; customer impact: a stale tab or a crafted request can put a wrong price in the owner's Telegram/email, or create a booking for a past date or a non-winter trip; fix: recompute total from the DB price/option, and reject past or out-of-season dates and non-bookable categories with 400.
- [Medium] lib/catalog.js:92-100,141-146 — the Transfer "Group size" filter compares against `capacity` (4). "1 – 2 people" and "5+ people" both hide the only transfer, and "3–5" and "5+" overlap at 5; customer impact: a couple choosing "1 – 2 people" sees "0 trips available"; fix: match when the group fits (`min ≤ capacity`), relabel the options "1–2 / 3–4 / 5+", or drop this filter.
- [Medium] components/BookingModal.js:234-237 + lib/tours-data.js:403 — a transfer is booked as a "trip" departure with capacity 4 for each day across all customers, so after one family of 4 books a transfer, that date is greyed out for everyone. The dialog also asks for no pickup place, destination, flight or time unless the admin added booking questions; customer impact: transfers sell out after one booking a day, and requests arrive without the details needed to do them; fix: treat transfer as timed/unlimited (`slot_limit: 'unlimited'`) and add default booking questions (from, to, flight/time, luggage).
- [Medium] app/activities/[slug]/page.js:50,119-133 — a trip that exists only in the database (added in admin) first renders "Trip not found … It may have been renamed or taken down" until Supabase answers. A truly unknown slug returns HTTP 200 (soft 404); customer impact: a shared link to a new trip flashes an error, and search engines index "Trip not found" pages; fix: track a `loading` state and show a skeleton until the query settles. Only then show not-found, and call `notFound()` from a server wrapper.
- [Medium] app/ (no not-found.js, error.js) — `/anything-wrong` shows the bare Next.js "404: This page could not be found." page in black and white, with no header, no link home, in English only, and with two `<title>` tags; customer impact: dead end; fix: add `app/not-found.js` with SiteHeader/Footer, a "Browse activities" button and t() strings, plus `app/error.js`.
- [Medium] app/signup/page.js:221 — "I agree to the terms and privacy policy" links both go to `/activities`; customer impact: a careful customer (EU/GDPR) clicks "privacy policy" and lands on the catalogue, which reads as a fake consent; fix: point them at real pages when they exist; until then remove the links and keep plain text.
- [Medium] components/SiteHeader.js:126 — the "Ask AI" button opens a browser `alert('AI assistant coming soon.')`. On phones it shows only a green dot with no text and no aria-label; customer impact: the first thing a curious visitor taps is a dead end with an English system popup; fix: hide the button until it exists, or make it open the real chat (`openChat()`).
- [Low] lib/ratings.js:39 (until REVIEWS-MODERATION.sql is run) — each page with stars fires two `tour_reviews?…&status=eq.approved` requests that fail with 400 before the fallback, which shows two red console errors on every trip page; customer impact: none visible, but it hides real errors and slows rating load; fix: owner runs REVIEWS-MODERATION.sql (or cache "no status column" after the first 400).

## Confusing

- [High] lib/i18n.js coverage — about, faq, contact, login, signup, reset, the trip page, BookingModal, Calendar (month/day names), Stars ("No ratings yet", "out of 5"), Gallery, TripPlace, OfflineBanner, the 404 page, lib/catalog.js sub-filter chips ("On snow", "Everything winter", "Instructors & schools", "Group size"…), lib/lessons.js levels and types, lib/bookingRef.js STATUS_LABEL, app/bookings/page.js body text, the home "What we do" block (app/page.js:109-182), SiteHeader "Winter"/"Info" columns and SiteFooter link labels are all hard-coded English. In zh/ru the header and cards switch, but the moment a customer opens a trip and the booking dialog, everything is English; customer impact: Chinese and Russian visitors switch language, then hit English on the pages where they spend money; fix: route these through t() (the trip.* keys already exist), starting with the trip page, BookingModal, Calendar and the catalog chips.
- [High] lib/i18n.js:914-923 — the language is never picked from the browser (`navigator.language`). Every first-time visitor gets English, and the saved language only applies after hydration (English flash); customer impact: a Chinese visitor has to find a small flag (on phones it is inside the person-icon menu) before reading anything; fix: on first visit with no saved `lang`, pick the first of `navigator.languages` that matches ka/ru/zh.
- [Medium] components/BookingModal.js:315-320 + components/Calendar.js:204-207 — the booking calendar opens on the current month (October). For winter activities (season 12-01→03-31), October and November are fully greyed out with no hint, and the "‹" button lets you go back into past months; customer impact: it looks as if nothing can be booked; fix: open the calendar on the first in-season, non-full month, show "Season: December – March" above it, and disable "‹" for months before today.
- [Medium] components/BookingModal.js:328-337 + lib/availability.js:171 — on today's date, time slots that have already passed (e.g. 09:00 at 15:00) can still be picked, and "today" is the visitor's device day, not Georgia's (UTC+4); customer impact: someone in Europe late in the evening, or China early in the morning, can request a lesson for a time that is already gone in Gudauri; fix: compute "now" in Asia/Tbilisi and disable slots earlier than now + a lead time (e.g. 2 h).
- [Medium] app/activities/[slug]/page.js:234,246,260-265,305 — the transfer page says "Spots open", "4 spots left", "90 ₾ per person", "Book a spot", "About this trip" and "Rate this trip" for a private car, and shows a weather tile with "—" for "Country-wide"; customer impact: a family of 4 reads 360 ₾ for one car and wonders whether "4 spots left" means the car is nearly full; fix: for `category === 'transfer'`, hide spots and weather, say "per car" (or the real pricing rule) and "Request a transfer".
- [Medium] app/activities/[slug]/page.js:309 + app/globals.css:827-833 — the disabled "Unavailable for now" button on the trip page uses the full green primary style. The only disabled style is scoped to `.booking-modal .book-btn[disabled]` (globals.css:562); customer impact: it looks clickable and does nothing; fix: add `.booking-card .book-btn:disabled{opacity:.5;cursor:not-allowed}` (e.g. in catalog.css).
- [Medium] lib/tours-data.js:405,419,433,465 — every winter activity lists "Languages: EN · GE · RU". There is no Chinese, and "GE" is a country code (the language is KA); customer impact: Chinese customers, the target market, read that no one speaks their language; fix: say "EN · KA · RU" and add "中文 on request" if true (owner to confirm).
- [Medium] components/BookingModal.js:502 — the total box says "Per person, all inclusions listed below. Paid on the day." Nothing is listed below in the dialog, and nothing says how to pay (cash/card, GEL only?); customer impact: uncertainty at the moment of commitment; fix: "Price per person. You pay on the day in cash or card (GEL)." (owner to confirm the payment method).
- [Medium] app/contact/page.js:25-30 — "Send a message" only sets `window.location.href = mailto:` with no feedback. On phones and PCs with no mail app (common for visitors from China who use WeChat or web mail), nothing happens; customer impact: they think the message was sent; fix: after the click, show "Your mail app should open. If it did not, write to … or use the chat", or post to the chat table instead.
- [Medium] components/ChatWidget.js:295-345 — signed-out chat collects no email, phone or WeChat/Telegram. A reply reaches them only if they come back on the same browser; customer impact: "We usually reply within a few hours", but the tourist never sees the reply; fix: after the first message, ask "Where should we answer? (email / WhatsApp / WeChat)" and store it on the conversation.
- [Medium] app/page.js:121-168 + components/SiteFooter.js:229-230 — the home "What we do" block and the footer promote Hiking, Camping and Mountaineering (all unavailable this winter), and the footer has no Transfer link; customer impact: winter visitors click into trips they cannot book; fix: add Transfer to the footer, and label the summer blocks "Summer 2027", or move them below the winter content.
- [Medium] app/activities/page.js:52,107 — the listing and trip pages first render placeholder data from lib/tours-data.js and silently keep it if Supabase errors (OfflineBanner only fires on DNS/network failure, not 4xx/5xx); customer impact: during an outage, visitors see sample prices and spots that are not real, and booking then fails; fix: when the query errors, show a small "Live availability could not load, prices may be out of date" note, and widen OfflineBanner to non-2xx responses.
- [Low] app/login/page.js:70-72 — the "Remember me" checkbox does nothing; customer impact: false promise on shared computers; fix: remove it.
- [Low] lib/i18n.js:89-90 — "1 trips available" (no plural), "trips" instead of "activities", and "No trips match those dates" also shows when no dates were picked (e.g. Winter → Freestyle, which has no items: lib/catalog.js:57); fix: add a `listing.countOne` key, say "activities", use a neutral "Nothing matches these filters" plus a Clear button, and hide the empty "Freestyle" chip.
- [Low] components/TourCard.js:271 + app/page.js — four winter cards all have `alt="Gudauri"` (the title), and the trip `region` shows twice on each card (tour-meta and tour-region-row); fix: alt = `${title} – ${subtitle}`; show the region once.
- [Low] app/activities/[slug]/page.js:202 — "0 views" shows on new trips; customer impact: weak social proof; fix: only show views at ≥ 20.
- [Low] app/contact/page.js:18 vs components/SiteFooter.js:239 — the contact page says "Gudauri, Georgia — winter base", the footer says "Tbilisi, Georgia"; fix: owner picks one.
- [Low] lib/i18n.js:40 ('chat.greeting') — "Hello! What can I help you with?" breaks the brief's no-exclamation-marks rule; fix: "Hello. What can we help you with?".

## Tiny technical fixes

- [High] app/layout.js:13-17 — every page (home, catalogue, every trip, login, 404) has the same title "Torito — Ski, Hikes, Camping & Climbs in Georgia" and a description about hikes/camping. There is no `metadataBase`, Open Graph, Twitter card, canonical, `app/sitemap.js` or `app/robots.js` (both return 404), and `/favicon.ico` is 404; customer impact: links shared on WeChat/Telegram/WhatsApp show no picture, Google shows one title for every page, and the brand does not match xnomads.ge; fix: add `metadataBase: new URL('https://www.xnomads.ge')`, default `openGraph`, `alternates.canonical`, `app/sitemap.js` and `app/robots.js`, plus per-trip `generateMetadata` (needs a server wrapper around the client trip page).
- [Medium] app/globals.css:827-833, 719-723, 707, 805 — white text on `--green-500` (#4fb3a0) is 2.53:1 (Book, View trip, hot-btn), and green "Spots open" text on white is also 2.53:1; WCAG AA needs 4.5:1. `--ink-soft` on `--page-bg` is 4.41:1 (just under); customer impact: hard to read in sunlight on a phone; fix: use `--green-700` (#3f8f80, 3.85) or darker (#2f7a6c ≈ 5:1) for button backgrounds and status text, and nudge `--ink-soft` to #557080.
- [Medium] app/globals.css:512 — `.booking-modal{max-height:calc(100vh - 40px)}`. On iOS Safari 100vh includes the hidden toolbar area, so the bottom "Request … places" button can sit under the browser bar; fix: add `max-height:calc(100dvh - 40px)` after it (same at header.css:19 and globals.css:194 hero).
- [Medium] components/BookingModal.js:250-260 — the dialog does not move focus into itself, does not trap Tab, and does not return focus to "Book" on close; customer impact: keyboard and screen-reader users tab behind the overlay; fix: focus the close button (or the h2) on mount, loop Tab inside `.booking-modal`, and restore focus on unmount.
- [Medium] components/BookingModal.js:177,200 + app/signup/page.js:158 — the phone is saved as `${dial} ${phone}`. A pasted "+86 138…" with the default dial +995 becomes "+995 +86 138…", even though the comment says pasting is handled; customer impact: the team cannot call back Chinese and Russian customers; fix: if the typed number starts with "+", use it as-is (or parse its dial code) and ignore the select.
- [Medium] app/api/bookings/route.js:94-124 — there is no idempotency key. A retry after a slow network, two tabs, or a double tap on a slow phone before React re-renders (BookingModal.js:505-510 relies only on `sending` state) can store duplicate trip requests; fix: send a client-generated `request_id` (uuid made when the dialog opens) and make it unique in `bookings`.
- [Medium] components/ChatWidget.js:335-350 — if a send fails, the user's bubble stays as if delivered, the input is already cleared, and there is no retry. Two quick sends before the conversation exists (Ask-a-question line plus a typed message) can create two conversations (`ensureConversation` has no in-flight guard); fix: mark the failed bubble "Not sent – tap to retry", restore the text, and cache the in-flight promise in `ensureConversation`.
- [Low] lib/season.js:49 — `money()` returns "0 ₾" when the price is missing (null/undefined → 0); customer impact: a trip with no price reads as free; fix: return "Price on request" when `n == null`.
- [Low] app/activities/[slug]/page.js:468 — review dates use `toLocaleDateString()` with no options ("10/16/2026" in en-US, different elsewhere), while bookings use "28 Dec 2026"; fix: one shared formatter with `{day:'numeric',month:'short',year:'numeric'}` and the active lang.
- [Low] components/HeaderToggles.js:24 + lib/i18n.js:921 — `localStorage.setItem('theme')` and `getItem('lang')` are not in try/catch. When storage is blocked, the theme toggle throws before `setTheme`, so the icon does not change; fix: wrap both in try/catch, as `setLang` already does.
- [Low] components/Gallery.js:35-42 — thumbnail buttons have no accessible name (`alt=""`, no aria-label), and there is no swipe on touch screens; fix: `aria-label={\`Show photo ${i+1}\`}` and simple touchstart/touchend swipe.
- [Low] components/AccountMenu.js:238,267 — `role="menu"` is used on a div of plain links with no `role="menuitem"` or arrow-key handling, which screen readers announce wrongly; fix: drop `role="menu"`/`aria-haspopup="menu"` (it is a disclosure).
- [Low] app/signup/page.js:123-145 — the validation order is password match → length → name → terms → phone, the email is never checked client-side, and errors appear under the button without `role="alert"`; fix: validate top to bottom (name, email, phone, password, terms) and add `role="alert"` to `.form-note.error`.
- [Low] components/AccountMenu.js:193 — the dev-only `?mockuser` stub hard-codes the owner's real name and email in source; fix: use "Test User / test@example.com".
- [Low] components/HotSection.js — not imported anywhere (the "Hot right now" strip is dead code since 1504b0b); fix: delete it or put it back on the home page.
